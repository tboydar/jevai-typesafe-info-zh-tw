# 04 — 使用案例（深入）

> 以下為工作範例，供評估參考。**尚未經過生產環境驗證。**
> 譯自 [`Satvik-codes/jevai-info-typesafe`](https://github.com/Satvik-codes/jevai-info-typesafe) 的 Use cases 章節。

## 1. 大規模受眾情緒分析（Audience sentiment at scale）

**原語：`score` + `choice` · 高流量留言串**

廣播公司想從 20,000 則留言判斷直播的整體觀眾反應（支持／批評／擔憂）。把留言丟給一般語言模型會耗光 token 預算；Jev 則是**分批閱讀**，每批回傳一個情緒分布，再由程式把各批加總成整體樣貌。

- 留言以批次計分，每批一個 score 問題，結果在程式端加總
- 保留每則留言的完整分布，所以罕見的強烈反應不會被平均掉
- 成本只隨 input tokens 而變，讓全語料分析在「逐則生成」做不到的地方變得可行
- 低信心的批次會**被標記**，而不是默默併入總數

## 2. 過濾搜尋結果（Filtering what a search returns）

**原語：`noul` × 4 · 生成前過濾**

搜尋助理抓出符合的文件交給語言 model 寫答案，但一份文件可能關鍵字相符卻已過時、與問題矛盾、或含有針對 model 的文字。Jev 先逐一檢查每一份文件。

- 每份文件四個是/否問題：是否切題、是否含可用事實、是否與問題矛盾、是否企圖指示 model
- 門檻以固定順序套用 — 安全性、矛盾、相關性 — 由第一個命中的決定
- 矛盾的文件被放進 prompt 的獨立段落，讓答案可以標示出分歧
- 重新調校是對已儲存答案的數字調整，不需再呼叫
- 這是**過濾器，不是安全邊界** — 寫作 prompt 仍把每份文件當成不可信

## 3. 把文章與留言分類（Sorting articles and comments into categories）

**原語：`choice` · 不確定時回傳寬鬆標籤**

發行商想把進來的文章與留言分進固定類別。不清楚的案例看起來跟清楚的幾乎一樣，這正是分類卡住的地方 — 答案上的**信心值**可以區分兩者。

- 一個問題即可涵蓋全部類別，可靠度約 240 個選項
- 決策看的是 **confidence**，不是最高選項的機率 — 狹窄領先與分散票數即使數字相同也是不同情境
- 低於門檻時，回傳較寬鬆的類別，由程式處理、不需第二次請求
- 再低一層，交給人工審查
- 在 TypeSafe 公開的範例中，這個 fallback 把 60 份文件中正確標籤從 39 提升到 48

## 4. 比對姓名與先前報導（Checking a name against earlier coverage）

**原語：`noul` × N · 僅供建議**

編輯想確認報導中提到的某人，是否出現在先前類似案件的報導裡。字串比對無法分辨「真正的先例」與「同名者」。

- state 只攜帶被比較的兩份紀錄，而非完整檔案庫
- 每個身分斷言都是獨立的 noul：姓氏、地點、車輛或角色、事件類型一致性
- **全部**都要通過門檻才會記錄關聯；任一失敗則轉人工
- 機率被保留下來，讓審查者看到「接近命中」而非一封被拒絕的結果
- 僅供建議 — 只註記草稿、永不發布。信心低不代表沒有先例
- 門檻依各檔案庫個別擬合，不能從上一個案例直接套用
